### Используемые паттерны и принципы проектирования


| Паттерн / Принцип                   | Класс / Файл                                                                         | Зачем он там нужен                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| :---------------------------------- | :----------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Single Responsibility Principle** | `WeaponConfig.cs`, `HitscanWeapon.cs`                                                | Каждый класс отвечает за одну задачу.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Facade + Context Object**         | `PlayerFacade.cs`, `PlayerContext.cs`, `EnemyBrain.cs`                               | Вся внутренняя информация и физика Игрока собирается в едином MB классе PlayerFacade, там же обрабатывается Update и происходит связь с внешним миром, информация передается в PlayerContext. Контекст удобно хранит все необходимые текущие данные об Игроке, и раздает их другим системам игрока, в основном стейтам. У Врага в силу его специфики проще - только фасад(EnemyBrain). Фасад скрывает внутренности от внешних систем, снижая связность |
| **State Machine**                   | `PlayerStateMachine.cs`, `IPlayerState.cs`, `EnemyStateMachine.cs`, `IEnemyState.cs` | Состояния игрока разделены на отдельные стейты, реализующие интерфейс IPlayerState. Избавляет код от ветвления, проще и удобнее расширять функционал                                                                                                                                                                                                                                                                                                   |
| **Observer**                        | `HealthEngine.cs`, `ExtractionPoint.cs`, `EnemyWaveSpawner.cs`                       | Игровые системы отвязаны друг от друга. Реагируют на срабатывание событий. <br>Реализовано через механизмы events/Action, что позволяет подписываться на изменения без создания жестких ссылок на чужие классы                                                                                                                                                                                                                                         |
| **Dependency Injection**            | `GlobalInstaller.cs`, `LevelInstaller.cs`, атрибуты `[Inject]`                       | Все нужные зависимости собираются централизованно, быстро и удобно.                                                                                                                                                                                                                                                                                                                                                                                    |
| **Strategy**                        | `IWeapon.cs`, `WeaponBase.cs`, `PlayerWeaponController.cs`                           | Игрок не знает о том, какое оружие у него в руках, он просто вызывает CurrentWeapon.TryFire. <br>Позволяет динамически менять алгоритмы поведения без изменения основного кода(контроллера)                                                                                                                                                                                                                                                            |
| **Асинхронность (UniTask)**         | `WeaponBase.cs`, `SceneLoaderService.cs`, `EnemyWaveSpawner.cs`                      | Длительные процессы идут параллельно без ущерба другим процессам и безопасно прерываются. UniTask не создает мусора в памяти                                                                                                                                                                                                                                                                                                                           |
| **Template Method**                 | `WeaponBase.cs`, `HitscanWeapon.cs`, `AssaultRifleWeapon.cs`                         | В Оружии используется базовый класс WeaponBase, его наследники реализуют только специфичную для них логику полета пули. Базовый класс задает жесткий алгоритм, защищая ядро механики от ошибок при создании новых типов оружия                                                                                                                                                                                                                         |
| **MVP**                             | `PlayerHUDPresenter.cs`, `SettingsModel.cs`, `LevelFlowUIView.cs` и др.              | Для UI. Model занимается своими делами, считает данные, создает события. View - MB классы, взаимодействующие с UI объектами на сцене. Presenter - связующее звено между моделью и представлением, слушает события модели и отдает вьюшке. <br>UI-слой независим от игровой логики                                                                                                                                                                      |
| **Object Pool**                     | `DecalManager.cs`, `VFXManager.cs`, `GlobalAudioService.cs`                          | Для оптимизации. Массив отключенных объектов, использование по необходимости, в циклическом массиве. Избавляет от тяжелых операция Instantiate/Destroy                                                                                                                                                                                                                                                                                                 |
| **Interface / Component**           | `IPickable.cs`, `IDamageable.cs`                                                     | Взаимодействие без лишней информации. Реализация Open/Closed Principle (OCP). <br>Выпущенному лучу оружия не нужно знать, в кого он попал, он просто ищет IDamageable                                                                                                                                                                                                                                                                                  |
| **Event Bus**                       | `GlobalAIEvents.cs`                                                                  | Сообщения об изменениях без лишней информации и связей, по подписке. Здесь враги могут реагировать на глобальные события без поиска конкретного источника                                                                                                                                                                                                                                                                                              |
| **Data-Driven Design**              | `ItemConfig.cs`, `WeaponConfig.cs`, `LevelWavesConfig.cs`                            | SO для конфигов. Вынос балансных настроек игры в удобные файлы.  Позволяет настраивать игру без вмешательства в кодовую базу                                                                                                                                                                                                                                                                                                                           |
| **Adapter**                         | `UnityInputService.cs`, `CharacterAnimationEvents.cs`                                | Создание переходников для соблюдения Dependency Inversion Principle. Адаптер инпута защищает от изменений в системе ввода                                                                                                                                                                                                                                                                                                                              |
