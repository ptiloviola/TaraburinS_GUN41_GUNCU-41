### Используемые паттерны проектирования

| Паттерн | Класс / Файл | Зачем он там нужен (Обоснование) |
| :--- | :--- | :--- |
| **State Machine** (Состояние) | `PlayerStateMachine.cs`, `PlayerIdleState.cs` и др. | Избавление от монолитного `Update()` с вложенными `switch/if`. Разделяет логику передвижения, прыжков и прицеливания на независимые классы, предотвращая конфликты анимаций и физики. |
| **Facade** (Фасад) | `PlayerFacade.cs`, `EnemyBrain.cs` | Скрывает сложную внутреннюю композицию сущности (инвентарь, IK-контроллеры, сенсоры). Предоставляет внешним системам простой интерфейс (`IDamageable`) для взаимодействия, снижая связность (coupling) кода. |
| **Observer** (Наблюдатель) | События в `PlayerFacade.cs` (`OnDeath`), `IInputService.cs` | Отвязывает игровые системы друг от друга. UI и системы ввода не опрашивают игрока каждый кадр (без `Update`), а реагируют только на срабатывание C#-событий, что экономит ресурсы CPU. |
| **Context Object** | `PlayerContext.cs` | Группирует все зависимости и данные состояния Игрока в один объект. Избавляет конструкторы стейтов от проблемы "раздувания" (Constructor Over-injection) и упрощает добавление новых зависимостей. |
| **Factory** (Фабрика) | `LootFactory.cs` | Инкапсулирует логику сложного создания объектов (спавн пушек с инъекцией зависимостей через `IInstantiator`), отвязывая игровую логику от жесткого API Zenject. |
